### Python C Roots

When I found out that Python is still developed in C, that left an impression in me. Some will know this since it is probably mentioned a lot but maybe not others. Regardless of the case if you can make a connection between some of the core Python source code written in C with how Python represents a string or an integer under the hood can also be impactful. It is likely that the actual code might be too much to digest so consider showing a simplified model. A good resource is Guido's appearance in Lex's podcast, I know for a fact that he talk briefly about that and Lex pointed out that his explanation must be a simplification. Aim to provide a model like that. This means that you have to prepare them for it, before you do that it is important that you explain or provide sufficienf information so that they can process it and be glad that I took the effort to prepare this for them. About this

It would be useful to also mention that Java was initially developed in C (a Java compiler written in C). They made the language robust enough to write a Java compiler written in Java and leave C behind. This was also the case for C++ probably so it might be imporant to mention this as a common approach to differentiate Python from other languages. Make them think why Guido advocates for developing Python in C, of course there are performance considerations but there may be other reasons that might be worthwhile mentioning. 

### Python C/C++ Interoperable Projects

It is important to mention open source projects that either leverage C/C++ code to make their application written in Python more performant. There are also projects that instead use Python to make their C/C++ code configurable dynamically such as hoomd-blue. Hoomd-blue is scientific computing open source project and I like the idea of mentioning it because it is a great example of this. You also want to mention other projects that follow this approach or similar but for other areas because the audience probably comes from other backgrounds other than science. It is imporant to always keep in mind your audience background and interests. This means that you need to research this to find about more projects in which C/C++ code is called from Python.

### When to reach out to C/C++

I think is very important to make clear under what circumstances you want to call C code from Python. If you do that but are not committed to maintaining the code as the languages evolve or the tooling evolves then probably you don't want to do it especially for production grade code. You also have to consider that improving or extending that code means that some of your developers need to know C. Also it would be useful for them that calling C code such as a Unix filter with a pipe could be a solution. The C code does not care about anything other than it reads from standard input, does data processing, and writes to standard output. It is the caller code in Python that knows from where the data has come and where it is going. Another reality is that the standard library of Python already provides the bindings to standard Unix tools and the C library (regex, timedate utils, etc.). Here's another point where you can show them that these nice tools that they use often are actually part of the glibc library. Probably what Python developers do is to implement the bindings. Here you can start talking about the `typing` module and `CPython`. The idea here is to present alternatives and maybe code snippets that illustrate their differences. And also use cases when you want to use one or the other. On the C++ side there's `pybind11` for exposing your C++ types to Python. I think this is also an interesting case to mention to them. And this brings to me the probable question what should I use, should I learn C or C++. And of course the answer depends on what they want to do and just make sure you prepare yourself to be objective not biased towards C. 

It is also important to mention to them that when you are trying to write performant C code you care about the actual instructions that the machine will perform. There's more of an overhead when you are writing C code but that, as everything else, as you write more code you will naturally write performant code. Here what matters is to teach them write performance aware code even if from Python (Casey Muratori mentioned). Teach them that if you can do your work by leveraging numpy arrays without looping through elements in a for loop you will be writing performant code. Of course, not always one can write sort of vectorizable code that way and you sometimes have to use an index. In that case it is important to know how Python lays out memory to avoid CPU caching problems (and this can be a difficult point, confusing, if they use Fortran based arrays because the favoring indexing is opposite to C-based arrays).
